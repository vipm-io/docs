VIPM 2026 Q3 f1 is a maintenance release that builds upon [VIPM 2026 Q3](2026.3.md) with SBOM accuracy and CLI reliability improvements, makes the VI Package Builder Save Version preview feature available outside Professional Edition, and fixes to Linux file path handling in VI package builds.

## Improvements

- **LabVIEW, NIPM, and VIPM versions in SBOMs**: SBOMs generated by `vipm sbom` now record the LabVIEW, NI Package Manager, and VIPM Desktop versions used to produce them (in the CycloneDX `metadata.tools.components` section), so each SBOM captures exactly which tool versions produced it. See the [SBOM output reference](../sbom/output-reference.md) for details.
- **Quieter NI package cache build**: The NI package cache build in `vipm sbom` and `vipm sync` now prints a heading and summary instead of one line per installed NI package.
- **Errors reported first**: `vipm sbom` and `vipm sync` now report errors ahead of progress and status output, so failures are easy to spot; previously an error could land at the bottom of a long run of output.

## Fixes

- **Linux file path handling**: Resolved issues with file path handling on Linux so that building VI packages works correctly — including `.vipb` files created on Windows that previously lost their path information when opened on Linux, and converting paths between Windows and Linux during VI package building. See the [tracking issue #132](https://github.com/vipm-io/vipm-desktop-issues/issues/132).
- **SBOM architecture mismatch**: Resolved an issue where generated SBOMs could attribute LabVIEW library VIs (from `vi.lib` or `instr.lib`) to the wrong NIPM package or the wrong architecture (32-bit vs 64-bit). See the [tracking issue #133](https://github.com/vipm-io/vipm-desktop-issues/issues/133).
- **"Save Version" available in Community and Pro**: Resolved an issue where the VI Package Builder **Save Version** preview feature always reported a Professional-Edition-only error regardless of your edition, which blocked the feature for everyone. It is now available in **Community Edition** (non-commercial use) and **Professional Edition**. See the [tracking issue #136](https://github.com/vipm-io/vipm-desktop-issues/issues/136).
- **Palette browser on Linux and Mac**: The palette browser tree now displays correctly on Linux and Mac; previously it could report errors and fail to show the palette hierarchy.
- **SBOM output folders**: `vipm sbom` now creates missing `--output` folders automatically, validates the output location before scanning begins, and reports file errors with the actual path and cause; previously a bad output path failed only after the full project scan, with a misleading disk-space/permissions hint. See [issue #139](https://github.com/vipm-io/vipm-desktop-issues/issues/139).
- **LabVIEW addons in SBOMs**: SBOMs now include every LabVIEW addon (LVAddons) that LabVIEW activates, attributing files to the addon version LabVIEW actually loads; previously some NI addons were silently missing from SBOMs, and addons with multiple installed version directories could be attributed to a stale version.
- **Long-running package builds**: `vipm build` now lets long-running VI package builds run to completion; previously a healthy build could be stopped after 60 seconds without visible progress and wrongly reported as VIPM Desktop being stuck.
