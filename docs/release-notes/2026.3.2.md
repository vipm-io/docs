---
title: VIPM 2026 Q3 f2
description: Maintenance release that fixes SBOM generation errors and missing components, improves LabVIEW startup timeout handling, and improves how packages with release-suffixed versions are read and how package versions are ordered when listed.
---

VIPM 2026 Q3 f2 is a maintenance release that builds upon [VIPM 2026 Q3](2026.3.md) and [VIPM 2026 Q3 f1](2026.3.1.md). It fixes some cases where SBOM generation returned an error, and others where components used in the project were not present in the output SBOM. It also improves LabVIEW startup timeout handling (and reduces occurrences of timeouts), improves how packages with release-suffixed versions (like some older OpenG packages) are read, and improves how package versions are ordered when listed.

## Improvements

- **Startup timeouts are reported as timeouts**: When LabVIEW takes too long to start, the command now reports a timeout (exit code `124`), and the message names the limit that was reached and how to increase the timeout value; previously this was reported as a different error (exit code `24` or `11`). Scripts that test for the earlier exit codes should be updated.
- **Pre-release version ordering**: Pre-release versions (like `1.0.0beta01-1`) now sort below their release version (`1.0.0`) and no longer satisfy a constraint like `>= 1.0.0`. Pre-release tags are ordered by letters, then by number: `1.0.0alpha2`, `1.0.0alpha12`, `1.0.0beta01`, `1.0.0`.
- **Faster package cache builds**: `vipm refresh` now builds a fresh package cache faster; some minor performance improvements were made when working with packages with release-suffixed versions.

## Fixes

- **"Unsaved changes" on an unedited project**: SBOM generation now refuses only real unsaved edits to the project (`.lvproj`), and the message says what differs; previously it sometimes failed with "unsaved changes" (exit code `23`) on a project that had not been edited, often in projects with NI driver dependencies. See [issue #146](https://github.com/vipm-io/vipm-desktop-issues/issues/146).
- **.NET assemblies called by name**: SBOM generation now succeeds on projects that call a .NET assembly by name, like `System.Windows.Forms` from the Global Assembly Cache; previously it failed with a "missing file" error (exit code `18`). See [issue #149](https://github.com/vipm-io/vipm-desktop-issues/issues/149).
- **Wildcard shared library names**: SBOM generation now resolves a shared library that a Call Library Function Node names with LabVIEW's wildcard pattern, like `lvzlib*.*`, to the library LabVIEW actually loads, and attributes that library to its package in the SBOM; previously it failed with a "missing file" error (exit code `18`) or silently left the library out of the SBOM. See [issue #150](https://github.com/vipm-io/vipm-desktop-issues/issues/150).
- **OpenG-format packages in SBOMs**: SBOM generation now reads packages correctly when they use the OpenG package format or have a release-suffixed version, like `oglib_lvzip 5.0.9-1`, and lists them in the SBOM with license, supplier, and hashes; previously it reported them as not installed or as a version mismatch and could leave them out of the SBOM. See [issue #151](https://github.com/vipm-io/vipm-desktop-issues/issues/151).
- **LabVIEW startup time**: Commands that start LabVIEW now wait up to 120 seconds for it to start, and the [`VIPM_LABVIEW_LAUNCH_TIMEOUT`](../cli/environment-variables.md#vipm_labview_launch_timeout) environment variable (in seconds) allows a longer wait; previously they failed when LabVIEW took more than 30 seconds to start, which is common on VMs and CI runners. See [issue #100](https://github.com/vipm-io/vipm-desktop-issues/issues/100).
- **Release-suffixed package versions**: Packages with release-suffixed versions (like the `-1` in `oglib_lvzip 5.0.9-1`) are now handled correctly by `vipm sbom`, `vipm uninstall`, `vipm info`, and `vipm search`, and in `.dragon` and `.vipc` files; previously they caused problems in some cases.
- **Installing from a package file**: `vipm install` from a package file now works for packages with release-suffixed versions (like the `-1` in `oglib_msgqueue 3.0-1`); previously it failed with "No Package Info found" or "Missing Name in Package section".
- **Version ordering in search and list**: `vipm search` and `vipm list` now order versions numerically, and search shows each package's latest matching version; previously they could show an older version of a package as the latest, because versions were compared as text (so `5.0.9` ranked above `5.0.10`).
